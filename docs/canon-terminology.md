# Canon och terminologi

## Pedagogisk profil

Språk: Svenska.

Svårighetsgrad: Erfaren grundnivå.

Läsarprofil: Verksamhetsarkitekter, IT-arkitekter och verksamhetsutvecklare med praktisk erfarenhet.

Ton: Tydlig, professionell, förklarande och praktisk.

Repetitionstakt: Centrala begrepp återkommer i flera sammanhang, men utan att boken blir grundläggande på nybörjarnivå.

## Återkommande case

Namn: Tullmyndigheten Atlantis

Syfte: Ett fiktivt case som gör det möjligt att visa skillnader mellan förmågor, processer, rutiner, tjänster, information, regler, roller och ansvar. Caset utgår från digital tullklarering, riskbedömning av varuflöden, inkommande deklarationer, kompletteringsbegäran, kontrollåtgärder och förvaltning av regler.

Regler:

- Caset ska vara realistiskt men inte beskriva någon faktisk myndighets interna arbete.
- Exempel ska användas pedagogiskt och får förenklas.
- Caset ska vara konsekvent genom boken.
- Exempel ska undvika känsliga operativa detaljer.

## Centrala begrepp

| Begrepp | Arbetsdefinition |
|---|---|
| Verksamhetsbeskrivning | En avsiktlig beskrivning av någon aspekt av verksamheten, framtagen för ett visst syfte |
| Förmåga | Huvudterm i boken. Vad en organisation behöver kunna göra för att uppfylla sitt uppdrag eller skapa värde. Kan första gången förklaras som verksamhetsförmåga |
| Process | Ett flöde av aktiviteter som över tid skapar ett resultat för en mottagare |
| Rutin | En mer detaljerad beskrivning av hur ett återkommande arbete ska utföras i praktiken |
| Tjänst | Ett erbjudande eller en funktion som ger värde till en mottagare |
| Produkt | Ett mer avgränsat erbjudande, resultat eller paket av funktionalitet som kan utvecklas, förvaltas och förbättras över tid. I myndighetskontext används begreppet främst för styrning och förvaltning, inte som kommersiell produkt |
| Digital produkt | En produkt med digital funktionalitet, ofta kopplad till team, roadmap, backlogg och teknisk förvaltning |
| Tjänstekarta | En strukturerad översikt över vilka tjänster verksamheten erbjuder och hur de relaterar till mottagare, behov och stödjande delar |
| Produktbeskrivning | En beskrivning av produktens syfte, mottagare, funktion, livscykel, ägarskap och koppling till nytta |
| Värdeflödesbeskrivning | En beskrivning av huvudstegen från behov till resultat och vilka förmågor, produkter och överlämningar som stödjer flödet |
| Värdeflöde | En övergripande sekvens som visar hur värde skapas från behov till resultat |
| Informationsobjekt | Något verksamheten behöver information om, hantera eller fatta beslut utifrån |
| Regel | Ett villkor som styr eller begränsar verksamhetens beslut och agerande |
| Affärsregel | En verksamhetsregel som styr eller begränsar beslut och agerande, ofta kopplad till policy, lag, riktlinje eller beslutad praxis |
| Roll | En uppsättning ansvar eller uppgifter som kan utföras av en person, grupp eller funktion |
| Ansvar | Det någon förväntas äga, besluta om, utföra eller följa upp |
| Syfte | Den användning, fråga eller beslutssituation som en verksamhetsbeskrivning ska stödja |
| Målgrupp | De personer eller roller som ska använda beskrivningen för att förstå, besluta, samordna eller utföra arbete |
| Modellnivå | Beskrivningens abstraktions- eller detaljnivå, från strategisk översikt till operativ instruktion |
| Verksamhetsförmåga | Något organisationen behöver kunna göra för att uppfylla sitt uppdrag, skapa värde eller nå ett mål |
| Förmågekarta | En strukturerad översikt över verksamhetens förmågor, ofta ordnad i områden och nivåer |
| Förmågenivå | En abstraktions- eller detaljnivå för en förmåga, exempelvis förmågeområde, förmåga och del-förmåga |
| Aktivitet | Ett avgränsat arbete eller steg i en process, formulerat med verb och objekt |
| Resultat | Det processen skapar, förändrar eller levererar när den är färdig |
| Mottagare | Den aktör, funktion, part eller efterföljande process som behöver resultatet |
| Startpunkt | Den händelse, signal eller situation som gör att en process börjar |
| Slutpunkt | Det tillstånd där processen är färdig och resultatet finns |
| Beslutspunkt | Ett vägval i processen där flödet kan ta olika riktningar |
| Överlämning | När arbete, ansvar eller information går från en aktör, roll eller funktion till en annan |
| Instruktion | En konkret vägledning för ett specifikt moment, ofta nära system, verktyg eller arbetssteg |
| Checklista | Ett stöd för att kontrollera att viktiga punkter inte missas |
| Rutinkandidat | Ett återkommande moment som kan behöva beskrivas som rutin, instruktion eller checklista |
| Rutinägare | Den roll eller funktion som ansvarar för att en rutin är korrekt, användbar och aktuell |
| Kandidat | Ett preliminärt ord, uttryck eller beskrivningsobjekt som kan bli en förmåga, process, rutin eller annan verksamhetsbeskrivning |
| Avgränsning | Ett medvetet beslut om vad en beskrivning omfattar, vad den inte omfattar och vilka angränsande beskrivningar som behövs |
| Identifieringsworkshop | En strukturerad workshop där utsagor sorteras till kandidater och preliminära beskrivningstyper |

| Nyttokedja | En kedja som visar sambandet mellan behov, fråga, beskrivning, beslut, åtgärd och uppföljning |
| Levande referens | En verksamhetsbeskrivning som används återkommande och därför behöver ägare, versionshantering och uppdatering |
| Modellförvaltning | Praktiken att hålla viktiga verksamhetsbeskrivningar användbara, aktuella och kopplade till ägarskap |
| Spårbarhet | Möjligheten att följa samband mellan exempelvis mål, förmågor, processer, information, system, rutiner och åtgärder |

## Regler för kapitel 11

- Vanliga misstag ska beskrivas som praktiska fallgropar, inte som kritik mot personer eller roller.
- Tullmyndighetscaset ska användas för att visa hur förmåga, process, rutin, tjänst, systemstöd och målbild kan blandas ihop.
- Rekommendationer ska vara korrigerande och användbara: formulera kontrollfrågor, åtgärder och sätt att dela upp modeller i vyer.
